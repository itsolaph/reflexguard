# ReflexGuard model report

Generated by `ml/train.py`. All data is synthetic (`ml/sim.py`); nothing here says how the model behaves on real pools. Numbers are for the integer model that runs on-chain.

## Setup

- Seed 7. 700 scenarios for each of 4 benign regimes (retail, whale, arb, burst) and 500 for each attack family (A pump-and-dump, B sandwich, C slow drip).
- Split 60/20/20 per scenario kind into train/val/test. Scenarios are independent pools, so there is no leakage across splits within a scenario.
- Positive label: only the swaps that unwind the attacker's position (A, B, C). The opening legs (pump, front-run, victim swap, drip swaps) are labelled 0: on-chain they look like a whale, a victim or an honest burst. A guard that fires on them anyway is counted as `early` for attack scenarios and as a false positive in the per-swap tables.
- Per-swap metrics use the shipped threshold. An *episode* is one scenario: **caught** = some positive-labelled swap reached the threshold; **early** = some swap *before* the first unwinding leg did (the pool would have been paused before the attacker started to unwind); **false-halt rate** = share of benign scenarios in which at least one swap reached the threshold (each of those would pause a legitimate pool).
- Threshold chosen on validation scenarios: the highest episode catch rate subject to a benign false-halt rate <= 2.0%. Best of 3 seeded restarts by the same criterion.

## 4. Where it fails

False halts on benign test scenarios by regime (halted / scenarios):

| regime | false halts |
|---|---|
| arb | 0 / 140 |
| burst | 14 / 140 |
| retail | 0 / 140 |
| whale | 2 / 140 |

Family A (test split) caught by time between the pump and the first unwinding leg:

| gap | scenarios | any unwinding leg flagged |
|---|---|---|
| 0-3 s | 27 | 24 |
| 3-6 s | 27 | 24 |
| 6-12 s | 25 | 20 |
| 12-21 s | 21 | 17 |

Structural limits, independent of the numbers above:

- The opening leg of A and B (the pump, the front-run) cannot be told from a whale swap or a victim swap. The guard can only react to the unwinding. The `early` columns show how often the guard fires before the unwind starts; for A and B that is by construction close to 0%, so the first unwinding leg of such an attack usually executes. Multi-leg unwinds are interrupted; a single-leg unwind is not.
- The callback is not instantaneous: the halt lands some seconds after the triggering swap. Swaps in between are not stopped.
- A whale swap that is arbitraged back within seconds looks like a pump-and-dump. The simulator includes only slow arbitrage-back (25 s or more) after whale swaps, so these numbers say nothing about fast arbitrage on a real chain.
